# Project brief

Use this user-owned document to describe a new project, milestone, or complex
idea before running `$start-work`. Copy it to the project root as
`PROJECT_BRIEF.md`, then replace the prompts below with as much context as you
currently have. It is fine to leave decisions unresolved; the planner will ask
for clarification rather than guess.

## Goal

_What should become possible, and what outcome would make this work useful?_

## People and use cases

_Who is this for, and what should they be able to do?_

## Important behavior

_Describe the main workflows, must-have capabilities, and important edge cases._

## Constraints

_List fixed technologies, compatibility needs, deadlines, security concerns,
or other limits._

## Out of scope

_What should this work deliberately avoid or postpone?_

## Known decisions

_Record choices that are already settled and who approved them._

## Open questions

_List anything you are unsure about or want the planner to help clarify._
